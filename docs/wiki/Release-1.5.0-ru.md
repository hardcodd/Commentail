# Commentail 1.5.0 — визуальный редактор комментариев

[English](Release-1.5.0.md) · Русский

Здесь описаны исходники 1.5.0 и порядок обновления. Наличие выпуска проверяйте
на [PyPI](https://pypi.org/project/commentail/); неопубликованный кандидат
устанавливается из проверенного локального wheel.

## Изменения

- Собственный визуальный редактор без сторонних зависимостей: полужирный,
  курсив, зачёркивание, ссылки, цитаты, списки, строчный код и блоки кода.
  Доступен переход к исходному Markdown; преобразование введённых маркеров
  можно отменить.
- Независимый выбор простого текста, Markdown или визуального редактора для
  гостей и зарегистрированных. Общие разрешения оформления задаются на Site
  и проверяются сервером. После установки/обновления остаётся простой текст.
- Создание, ответ и правка сохраняют независимые черновики внутри страницы при
  навигации и исправимых ошибках. Это не постоянное автосохранение.
- Интерфейс на английском, русском, немецком, французском, испанском и
  бразильском португальском; условная загрузка ресурсов и обычное поле без JS.
- Единообразные иконки, свёрнутая справка по клавиатуре, лимит возле редактора
  и отдельное уведомление о письмах с ответами. При запуске и переключении
  режима не появляются дополнительные обучающие сообщения.
- Опубликованные блоки кода учитывают цвета сайта вместо фиксированного светлого фона.
- Ответ на собственный комментарий запрещён: для аккаунтов по учётной записи,
  для гостей по нормализованному email. Старые ответы самому себе сохраняются.

## Обновление с 1.4.1

1. Повторите обновление на отдельной копии с локальной почтой. Сохраните БД,
   пакет, версии зависимостей, настройки, шаблоны и секреты. На время итоговой
   копии/переключения остановите запись и worker. Сохраните прежний секретный ключ.
2. Установите проверенный wheel 1.5.0, выполните `migrate`, `check` и
   `collectstatic --noinput`, обновите кеш статики и перезапустите приложение
   и worker обычной процедурой проекта.
3. Миграция `0020` добавляет `text_format` комментариям/правкам и настройки
   редактора Site. Старый текст остаётся простым, в том числе при правке:
   Markdown-маркеры не переосмысливаются. Настройки не переписывают публикации.
4. Проверьте переопределения `block.html`, `form.html`, `edit-form.html` и
   `comment.html`. Форматированному телу нужен блочный контейнер, не абзац.
   Сохраните textarea, серверные действия, CSRF и атрибуты/ресурсы редактора;
   см. [контракт шаблонов](Template-contract.md).
5. Выберите режимы в **Комментарии → Настройки сайта → Редактор комментариев**.
   Проверьте обе аудитории, разрешённое/запрещённое оформление, ответ другому
   автору, допустимую правку, ошибки, отмену и независимые черновики с JS и без.

Схему можно откатить, но обратная `0020` удаляет сведения о формате и настройки
редактора. Понижение версии не сохраняет смысл новых форматированных комментариев.
При необходимости восстановите согласованную копию прежней БД и пакета, учитывая
новые записи и письма после создания копии.

Для более ранних версий также выполните промежуточные инструкции, особенно
[1.4.0](Release-1.4.0-ru.md) и [необратимую миграцию 1.3.1](Release-1.3.1.md).

## Совместимость и ограничения

Сохраняются Python 3.12–3.14, Wagtail 7.4.3+ с Django 5.2/6.0 и Wagtail 8.0.x
с Django 5.2/6.0/6.1, файловая SQLite и PostgreSQL 16. Зависимости и границы
поддержки не изменились.

Поддерживается ограниченный Markdown, а не произвольный HTML или весь CommonMark.
Вложенные цитаты, код с указанием языка, сложные пункты списков и многострочные ссылки могут оставаться
только в исходном режиме. Пробелы кода сохраняются; граничные пробелы абзацев и
списков могут нормализоваться при экспорте визуального вида.
См. [руководство редактора](Comment-editor-ru.md).

Проверены настольные сценарии Firefox и согласованные сценарии озвучивания
VoiceOver. Это не полная проверка доступности/WCAG. Физические устройства, IME,
автозамена и диктовка остаются вне выполненных проверок.
CI должен пройти для точного публикуемого коммита; прежняя матрица не проверяет
этот выпуск. Тема сайта, права и реальная доставка писем требуют приёмки проекта.
