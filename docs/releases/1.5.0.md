# Commentail 1.5.0 — visual comment editor

English · [Русский](1.5.0.ru.md)

These notes describe the 1.5.0 source and upgrade contract. Check
[PyPI](https://pypi.org/project/commentail/) for release availability;
unpublished candidates use a reviewed local wheel.

## Changes

- An owned, dependency-free visual editor with bold, italic, strikethrough,
  links, quotes, lists, inline code and code blocks; switch to Markdown source
  when needed. Typed Markdown shortcuts are undoable.
- Independent Plain text / Markdown / Visual editor modes for guests and
  registered users, with shared per-Site formatting permissions enforced by
  the server. Plain text remains the default after installation or upgrade.
- Create, reply and author-edit forms preserve separate in-page drafts across
  navigation and recoverable failures. This is not persistent autosaving.
- English, Russian, German, French, Spanish and Brazilian Portuguese UI;
  conditional editor assets and a native textarea fallback without JavaScript.
- Consistent toolbar icons, collapsed keyboard help, editor-adjacent length
  limits and a distinct reply-email notice. Routine initialization and mode
  switches do not display instructional status messages.
- Published code blocks follow host colors instead of forcing a light background.
- Authors cannot reply to their own comments. Accounts use account identity;
  guests use normalized email. Existing self-replies remain visible.

## Upgrade from 1.4.1

1. Rehearse on a separate copy, with local mail. Back up the database, package,
   dependency versions, settings, overrides and secrets; pause writers and workers
   for the final backup/cutover. Keep the same secret key.
2. Install the reviewed 1.5.0 wheel, run `migrate`, `check` and
   `collectstatic --noinput`, then refresh cached assets and restart the app and
   workers through the host deployment process.
3. Migration `0020` adds comment/revision `text_format` and Site editor settings.
   Existing text is explicitly plain: literal Markdown markers are not reinterpreted,
   including on editing. Settings changes do not rewrite published comments.
4. Review overrides of `block.html`, `form.html`, `edit-form.html` and
   `comment.html`. Rich comment bodies need a block container, not a paragraph.
   Keep the native textarea, server actions, CSRF and editor resource/data hooks;
   see the [template contract](../wiki/Template-contract.md).
5. Enable the desired modes under **Comments → Site settings → Comment editor**.
   Test both audiences, permitted/forbidden formats, replies to another author,
   eligible edits, errors, cancellation and independent drafts, with and without JS.

The schema additions are reversible, but reversing `0020` discards format metadata
and editor settings. Downgrading cannot preserve the meaning of newly formatted
comments. Restore the matched pre-upgrade database/package backup when rollback
is necessary, accounting for writes and mail after that backup.

For upgrades from older versions, also follow all intervening notes, particularly
[1.4.0](1.4.0.md) and the irreversible [1.3.1 migration procedure](1.3.1.md).

## Compatibility and limits

Python 3.12–3.14, Wagtail 7.4.3+ / Django 5.2 or 6.0, and Wagtail 8.0.x /
Django 5.2, 6.0 or 6.1 remain the supported combinations, on file SQLite and
PostgreSQL 16. No dependency or support-bound changes.

The editor uses a limited Markdown dialect, not arbitrary HTML or full CommonMark.
Nested quotes, language-labelled code fences, complex list items and cross-line links can remain source-only.
Code whitespace is preserved; surrounding paragraph/list boundary spaces can be
normalized on visual export. See the [editor guide](../wiki/Comment-editor.md).

Desktop Firefox interaction and focused VoiceOver speech scenarios have been
reviewed. This is not full accessibility/WCAG certification. Physical devices,
IME, autocorrection and dictation remain outside the completed checks.
Hosted CI must pass for the exact publishing commit; older matrix results do not
verify this release. Host themes, permissions and actual mail delivery require
site-specific acceptance.
